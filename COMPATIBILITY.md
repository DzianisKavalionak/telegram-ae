# Совместимость JSX и причины ошибок

## Точка наведения камеры

3 ноября 2026 года при запуске первого пакета получено сообщение TypeError: null is not an object на строке 242. На этой строке скрипт вызывал setValue у результата поиска свойства с ошибочным именем ADBE Point of Interest.

Видимая надпись Point of Interest у камеры имеет внутреннее имя ADBE Anchor Point внутри ADBE Transform Group. Именно этот match name нужно использовать в ExtendScript. Поиск по ошибочному внутреннему имени вернул null, поэтому последующий setValue остановил сборку.

Общий сборщик получает это свойство через requiredProperty. Функция проверяет существование группы и свойства и сообщает, какое именно свойство отсутствует, вместо неясной ошибки обращения к null. Таким же способом получаются остальные обязательные свойства камеры.

Для CAMERA_RIG применён setParentWithJump с последующей явной настройкой локальных Position и Point of Interest. Это сохраняет локальные преобразования камеры и позволяет родительскому контроллеру задавать ракурс без автоматической компенсации его вращения.

Основание для правильного имени: [пример настройки камеры в Adobe Community](https://community.adobe.com/questions-529/adding-a-camera-and-orbit-null-with-extendscript-63253). Поведение parent и setParentWithJump описано в [After Effects Scripting Guide](https://ae-scripting.docsforadobe.dev/layer/layer/#layerparent).

Причина установлена по строке исходника, сообщению пользователя и справке. При первом исправлении 3 ноября повторного запуска не было. 7 ноября исправленный общий сборщик успешно создал новый AEP в AE 26.5x89; композиция отрендерена штатным aerender.

## Camera Lens Blur и общая 3D-плоскость

Общее размытие создаётся настоящим эффектом ADBE Camera Lens Blur на верхнем 2D adjustment layer. Обязательный параметр Blur Radius имеет match name ADBE Camera Lens Blur-0001 и получается через requiredProperty. Радиус задан с первого кадра и достигает точного 0 к концу прокрутки. По умолчанию нативная глубина резкости камеры выключена.

Документация эффекта: [Adobe Camera Lens Blur](https://helpx.adobe.com/uk/after-effects/desktop/apply-effects-and-animation-presets/list-of-effects/blur-sharpen-effects.html). Пример обращения к Blur Radius по match name: [Adobe Community](https://community.adobe.com/questions-529/this-script-replaces-all-instances-of-one-effect-with-another-but-it-doesn-t-work-help-51298).

Фон, лента и профиль рендерятся одной 3D-прекомпозицией с выключенным Collapse Transformations. Это связывает их перспективу при движении камеры. Размер плоскости учитывает наиболее далёкое положение камеры и `sceneOverscan`, по умолчанию 1,25. При открытии старых конфигураций сборщик также читает запас из `background3D.overscan`. При изменении траектории камеры проверяй покрытие кадра.

## Изолированная сборка и контроль рендера

`AfterFX.exe -m -noui -r` запускается на неактивном рабочем столе Windows. `Prepare_Project.jsx` проверяет токен и пустой стартовый проект, создаёт основную композицию и рендерит её через очередь AE. При `-Resume` он открывает сохранённый AEP в изолированном экземпляре и отключает прежние элементы очереди перед добавлением текущего задания.

Проверяй статус `DONE`, наличие каждого TIFF-кадра и параметры готового MP4 через FFprobe. У RenderQueueItem не следует предполагать наличие свойства index. В отчёте сохраняется число элементов очереди.

Отдельный рабочий стол задаётся через `STARTUPINFO.lpDesktop` в Win32. [Документация Microsoft](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/ns-processthreadsapi-startupinfow).

## Промежуточный рендер и размер AVI

На AE 26.5 16,08-секундная 4K-композиция выдала Lossless AVI с заголовком на 402 кадра, но реально содержала только 86 кадров и обрывалась у 2 ГБ; aerender при этом сообщил об успехе. Для предотвращения тихого обрезания рендер использует TIFF Sequence with Alpha в отдельную папку задания. Перед кодированием проверяется наличие каждого ожидаемого кадра, после кодирования FFprobe проверяет число кадров и длительность MP4. Скрипт удаляет кадры после успешной технической проверки и сохраняет их при ошибке.

## Совместимость версий пакета

Новая сборка использует `VERSION` и `settings.templateVersion`. При расхождении перечитай правила из актуальной ревизии и подготовь конфигурацию заново с действующими настройками. Продолжение `-Resume` использует скрипты и `VERSION` исходной сборки AEP. Пакеты, созданные до появления `VERSION`, открываются и рендерятся со своими исходными скриптами.

## Порядок исправления следующих ошибок

1. Сопоставить номер строки с конкретной выданной версией JSX.
2. Найти отсутствующую группу, свойство или неверное значение.
3. Проверить правильный API по документации или фактическому свойству AE, если пользователь разрешил такой просмотр.
4. Исправить общий сборщик и записать применимое ко всем проектам правило.
5. Автоматически синхронизировать общий код и правила в GitHub в текущей задаче.
6. Выдать новый пакет, сохранив предыдущую версию; указать фактический статус проверки.
